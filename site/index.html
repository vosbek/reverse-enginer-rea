Static reverse engineering

Reverse engineer anything. Run nothing.

Clearbox reads a codebase or a folder of binaries and explains how it works: its architecture, how a feature is wired, what it can do to your machine, and how to rebuild it. Every claim points to a file, a line, and the SHA-256 of the bytes it read.

Case study 01

We pointed Clearbox at REA.

REA (“Reverse Engineer Anything”) is a popular MCP server for agent-driven reverse engineering. We scanned commit a95795c to understand what it is and what it does to the machine it runs on. It took 14 seconds and nothing ran.

504,490lines of code across 2,530 source files (43% tests)
561locked npm packages behind 38 declared runtime dependencies
103agent tool names declared in source
185high-severity capability sites in production code
Process control

It launches programs and drives terminals.

Process-spawning calls appear in 106 non-test files, and 5 files drive an interactive terminal through node-pty. That is how REA runs Ghidra, Hopper, and the targets themselves. It also means a malicious target gets the same user permissions.

Host changes

It can install software as root.

The Linux Hopper installer calls apt-get, dnf, or pacman and escalates with pkexec. REA documents this and asks first. Clearbox found it in one file, with line numbers, before anything was installed.

Feature trace

Its setup edits your agents' config.

Tracing “setup agent client configuration” lands on 10 seed files reached from scripts/rea.mjs → src/cli.ts → src/cli/setupCommands.ts, plus a 10-step rebuild plan, 32 environment variables, and 36 test files that pin the behavior.

Side by side

What runs on your machine?

Reverse-engineering tools open untrusted code by definition. The safest one does the most it can without executing anything, and tells you exactly what it read.

Where REA wins

REA can decompile native code through Ghidra, IDA, and Hopper, observe running browsers and Electron apps, and drive Android devices. Clearbox does none of that. Use Clearbox first to map the target and decide what deserves deeper work, then run a decompiler inside a disposable VM.

Templates

Ask a question, get a report.

A template is a list of questions, each answered by views from the analyzers. Five ship built in. Writing your own takes a minute and no code.

  • overviewWhat is it made of, how is it organized, where is the weight, and how do you get in?
  • feature-traceWhere does a feature live, how is it reached, what does it need, and in what order do you rebuild it?
  • security-surfaceProcesses, network, files, privileges, secrets (redacted), and text aimed at AI agents.
  • dependency-auditDeclared versus actually imported, unused packages, and install-time scripts.
  • binary-triageELF, PE, Mach-O, WASM, DEX, and archives: architecture, sections, entropy, strings.

Visibility

Every claim says how it knows.

Reports label each view with how its facts were established, so you know which ones to double-check.

parsed

Read by a real parser: Python's ast, JSON, TOML, or binary headers. Treat these as facts about the bytes.

pattern

Matched a documented regular expression. Click the row to see the exact line and judge it yourself.

heuristic

Inferred from scores or graph shape, like which files make up a feature. Use these as a starting point.

Ledger

Every file read, its byte count, its SHA-256, and which analyzers used it.

Blind spots

Dynamic imports, aliases, oversized files, and other things the run could not see.

Reproducible

The same input gives the same content hash, so two people can confirm they reviewed the same thing.

Self-contained

HTML reports carry a strict CSP: no external requests, and target text is never parsed as markup.

Install

Python 3.11 and a folder.

Clone or extract the target first. Clearbox never fetches anything for you, which keeps the network out of the picture.

terminal
pip install git+https://github.com/vosbek/reverse-enginer-rea
clearbox scan ./some-app                    # overview
clearbox scan ./some-app -t security-surface
clearbox trace ./some-app "search notes"    # feature trace
clearbox templates                          # list templates

Reports land in clearbox-reports/ as HTML, Markdown, and JSON. Clearbox refuses to write inside the target.

MCP config for your agent
{
  "mcpServers": {
    "clearbox": {
      "command": "clearbox",
      "args": ["mcp", "--allow-root", "/path/to/targets"]
    }
  }
}

The agent gets four read-only tools and can only see what is under --allow-root.
