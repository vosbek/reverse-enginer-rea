Understand how software works without running it

Clearbox is a static analysis tool for reverse engineering. Point it at a folder of source code or executables and it explains the architecture, where a feature lives and how to rebuild it, and what the program is able to do to the machine it runs on. Each statement in a report cites the file, the line, and the SHA-256 of the bytes it was read from.

How a scan works

Clearbox reads the target through a single read-only workspace. That workspace refuses paths outside the folder and does not follow symlinks. It caps how much it reads and records every file in a ledger. Eight analyzers turn those bytes into facts. Python is parsed with its own ast module, manifests with JSON and TOML parsers, and executables with struct, so nothing is imported, evaluated, or run. A template decides which questions the report answers, and the report can be read in a browser, diffed as Markdown, consumed as JSON, or queried by an AI agent.

The full description, with how each guarantee is enforced, is in How Clearbox works.

What the reports answer

Where a feature lives, and how to rebuild it

Describe a feature in plain words. Clearbox scores files by their paths, symbol names and contents, then follows the import graph. The result shows how execution reaches the feature, which packages and settings it depends on, which existing tests cover it, and the order in which to rebuild its files so each step depends only on earlier ones.

Example: the setup feature of REA

What the program can do to your machine

Documented rules find process launches, network access, file deletion, privilege requests, disabled certificate checks, unsafe deserialization, committed credentials, and text written to manipulate AI agents. Production code is counted separately from tests and documentation. Credentials are masked before they reach the report.

Example: REA's security surface

What a binary is, who signed it, and what it imports

Executables and archives are identified by their bytes. For Windows programs Clearbox also reads the import table, version resource, signer names, hardening flags, and UTF-16 strings, and translates imported APIs into capabilities such as “starts other programs” or “writes the registry”.

Example: Spotify's Windows installer

How a codebase is organized

Files are grouped into areas, and a matrix shows which areas import which. The overview also lists the most-imported files, import cycles, and dependencies that are declared but never used.

Safety model

Reverse-engineering tools handle untrusted input by definition. These properties are enforced in Clearbox's code and checked by its test suite.

Read-only access
Files are opened with O_RDONLY | O_NOFOLLOW. Paths outside the target and symlinks are refused, and reports cannot be written inside the target.
No execution or network
A test parses Clearbox's own source and fails if it imports subprocess, socket, urllib or similar modules, or calls eval, exec or os.system.
A record of every read
Each report lists every file read with its SHA-256, plus a content hash that is identical across re-runs on the same input.
Stated limits
Computed imports, path aliases, oversized files and the reach of pattern rules are listed as blind spots on every report.
Labeled confidence
Each result says whether it was parsed from a structure, matched by a documented pattern, or inferred heuristically.
Agent isolation
Over MCP, agents can only reach folders named with --allow-root, and text from the target is fenced with a random nonce so it cannot pass as instructions.

Compared with REA

REA is a capable tool that drives decompilers and live programs. Clearbox covers the analysis that can be done without running anything, with far less code to trust.

Install

Clearbox needs Python 3.11 or newer and nothing else. Clone or extract the target yourself; Clearbox never downloads anything.

Command line
pip install git+https://github.com/vosbek/reverse-enginer-rea

clearbox scan ./some-app                     # architecture overview
clearbox scan ./some-app -t security-surface
clearbox scan ./installers -t binary-triage
clearbox trace ./some-app "search notes"     # feature trace
MCP configuration for an AI agent
{
  "mcpServers": {
    "clearbox": {
      "command": "clearbox",
      "args": ["mcp", "--allow-root", "/path/to/targets"]
    }
  }
}
