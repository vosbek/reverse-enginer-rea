Case study

Spotify for Windows, decoded without running it, then rebuilt as mySpotify

We took Spotify's Windows installer and asked Clearbox what it is and what it does to a PC. The first pass showed a gap in Clearbox, so we fixed it. Then we built our own player on Spotify's official API, checked it with the same rules, and shipped it as a Windows program.

What we did

Eight steps, each with a receipt

Every step links to the commit, report, or release it produced.

  1. Quarantined the installer

    The official download, SpotifySetup.exe (1,074,664 bytes, SHA-256 b7d990f2…1258b), went into its own folder. It was never run.

  2. First pass: Clearbox fell short

    Clearbox 0.1 identified a 64-bit Windows program, listed its 7 sections and pulled 12 strings. It could not say who signed it, what it imports, or what it is allowed to do. For a Windows binary that is most of the story.

  3. Taught Clearbox to read Windows programs

    We added a PE decoder: the import table, version resource, signer names from the certificate table, hardening flags, UTF-16 strings, and a map from Windows APIs to plain-language capabilities. A synthetic test executable guards it.

    Commitb84f954pe.py

  4. Re-ran the triage

    In 0.15 seconds: 8 imported DLLs with 193 functions, 10 capabilities, the product identity, 4 certificate names, and 213 readable UTF-16 strings.

    Installer reportJSON

  5. Chose how to rebuild

    The installer carries no app features, so we mapped what any user sees in the desktop app to Spotify's public Web API, and chose the official playback SDK over reimplementing Spotify's private protocol.

  6. Built mySpotify

    About 1,550 lines: a standard-library Python launcher and a plain JavaScript app with no build step. It's tested against a mocked Spotify with 18 browser checks and 6 server tests.

    Commit7283b99Repository

  7. Checked it with the same rules

    Clearbox's security scan of mySpotify finds two host capabilities, both network calls: one to the Web API and one to Spotify's sign-in token endpoint.

    mySpotify security report

  8. Shipped a Windows program

    GitHub Actions builds mySpotify.exe on Windows, runs the tests, starts the program, checks that it serves the app, and publishes it with a checksum.

    Releasev1.1.0Commitc948139Build workflow
Anatomy of SpotifySetup.exe

A 1 MB downloader, signed by Spotify AB

Spotify Installer 1.3.4.258, original name installer_stub.exe, 64-bit Windows GUI. Signed by Spotify AB through DigiCert's G4 code-signing CA, with a 2025 timestamp. Built with MSVC with ASLR and DEP enabled, and a deterministic build timestamp.

Findings

What the evidence says the installer does

Each finding shows the bytes behind it and how sure we are. "Parsed" means read from a structure; "inferred" means a conclusion from parsed facts that a disassembler would confirm.

Parsed

It's a downloader, not the app

The original filename is installer_stub.exe. The real client, SpotifyFullSetup, is fetched at install time from Spotify's CDN, with the CPU architecture filled into the URL.

Evidence
0x1029fcOriginalFilename: installer_stub.exe
0x63e92https://download.scdn.co/SpotifyFullSetup.exe (UTF-16)
Parsed

The download URL lives outside the code

The template URL sits in a 104-byte block appended after the program image, just before the signature, with a small binary header in front of it. Keeping it out of the compiled code lets one build be pointed at different downloads. That's our reading of why; the bytes themselves are certain.

Evidence
0x103c00104-byte block between .reloc and the certificate table
0x103c3bhttps://download.scdn.co/SpotifyFullSetup[ARCH].exe
Inferred

Its networking is hidden from the import table

None of the 8 imported DLLs handles networking, yet WININET.dll appears in the binary's strings and it imports LoadLibraryExW and GetProcAddress. It most likely loads WinINet at runtime. A scanner that trusted imports alone would call this program offline.

Evidence
0xa6d90WININET.dll
importsKERNEL32!LoadLibraryExW, KERNEL32!GetProcAddress

What the installer can't tell us: anything about the app's screens or features. Those come with the full client the stub downloads, and we chose not to run it. The recon script applies the same static triage to an existing %APPDATA%\Spotify install.

Choosing how to rebuild

Three ways to play Spotify audio in your own app

Spotify's audio is DRM-protected. That single fact decides most of the architecture.

RouteHow audio playsTrade-off
Official SDK ChosenSpotify's Web Playback SDK, inside a browser engine that includes the Widevine DRM module (Edge, Chrome, Firefox)Within Spotify's developer terms and stable. Needs Premium, and the player runs in a browser window.
Reimplement the protocolAn open-source library such as librespot talks to Spotify's private protocol and decrypts audio itselfNative and light, but against Spotify's terms, breaks when Spotify changes things, and risks the account.
Desktop wrapperElectron or Tauri around the web appNeither includes Widevine. The one Electron build that does needs third-party licensing and adds about 150 MB.
How mySpotify works

A local launcher, a browser app, and Spotify's own services

mySpotify.exe only serves the app's files on 127.0.0.1. Sign-in, library calls and audio go straight from the browser to Spotify, so your token never passes through the launcher.

18 browser checks

Sign-in gating, the 2026 response shapes, play and like requests, the 10-result search limit, the top-tracks fallback, device transfer, keyboard control, phone width, and no page errors.

6 server tests

Path traversal is blocked, security headers are set, only 127.0.0.1 is answered, and there are no directory listings.

Exe smoke test on Windows

Every build starts mySpotify.exe on a Windows runner and checks that it serves the app, its scripts, and the sign-in callback.

Why it opens in a browser window. Spotify only lets third-party apps play audio through its Web Playback SDK, which needs a browser engine with Widevine DRM. For a window of its own, with no tabs or address bar, choose Apps › Install this site as an app in Edge. It is still Edge underneath, because that is what lets the music play. The exe isn't code-signed yet, so Windows asks for confirmation on first run.

Limits

What this case study doesn't claim

1

Static only. We read the installer; we never ran it or the full client. The runtime networking finding is an inference that a disassembler would confirm.

2

Tested against a mock. mySpotify's checks run against a mocked Spotify. Its first sign-in with a real account is the first live test.

3

Spotify's rules apply. Playback needs Premium, and apps in development mode allow up to 5 users, each added in the dashboard.

4

Not affiliated. mySpotify is an independent app on Spotify's public API. The installer is not redistributed here; only Clearbox's reports are.
