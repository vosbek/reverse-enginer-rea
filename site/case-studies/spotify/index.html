Spotify for Windows, decoded without running it and rebuilt as mySpotify

We asked what Spotify's Windows installer is and what it does to a PC, using only its bytes. Answering properly required extending Clearbox. We then built a replacement player on Spotify's official API, held it to the same checks, and released it as a Windows program.

Target SpotifySetup.exe 1.3.4.258Tool Clearbox 0.2.0Result mySpotify v1.1.0

Summary

The 1 MB file Spotify serves as its Windows download is not the app. It is a signed downloader that fetches the real client from Spotify's CDN, installs it for the current user, and coordinates with Spotify's updater.

Clearbox reached that conclusion in 0.15 seconds without executing anything. It read the file's import table (193 functions from 8 DLLs), its version resource, the names in its certificate table, and 213 readable UTF-16 strings. Two details stood out. The download address is stored in a small block appended after the program code. The installer's networking library is loaded at runtime rather than declared, so a scanner that trusts the import table would conclude the program never touches the network.

Because the installer carries none of the app's features, we rebuilt the player from Spotify's public Web API. mySpotify is about 1,550 lines. A security scan finds exactly two host capabilities in it, both network requests to Spotify.

Method

  1. Quarantine the installer

    The official download (1,074,664 bytes, SHA-256 b7d990f2…1258b) was placed in its own folder and never run.

  2. First pass, and the gap it exposed

    Clearbox 0.1 identified a 64-bit Windows program, listed its seven sections and extracted twelve strings. It could not say who signed the file, what it imports, or what it is permitted to do. For a Windows binary that is most of the useful information.

  3. Extend Clearbox to read Windows programs

    We added a PE decoder covering the import table, version resource, certificate signer names, hardening flags and UTF-16 strings, plus a mapping from Windows APIs to capabilities. A synthetic executable in the test suite guards it.

    Commit b84f954pe.py

  4. Re-run the triage

    The second pass took 0.15 seconds and produced the findings below.

    Installer reportReport data (JSON)

  5. Choose a rebuild route

    We mapped what a user sees in the desktop app to Spotify's public Web API. We chose Spotify's official playback SDK over reimplementing its private protocol.

  6. Build mySpotify

    A Python launcher that uses only the standard library and a plain JavaScript app with no build step. It is tested against a mocked Spotify with 18 browser checks and 6 server tests.

    Two host capabilities were found, both network requests to Spotify.

How the binary was read

No disassembler, debugger or sandbox was involved, and the file was never executed. A Windows executable is a documented container format (PE/COFF). Clearbox's PE decoder, about 200 lines of Python, reads it the way the Windows loader would, using struct to unpack fixed-size records at known offsets and bounds-checking every read. The table lists each structure it read from this file, in order, and what that structure revealed. Figures and tables referred to here appear in the next section.

What this approach does not cover. The 363 KB of machine code in .text was not disassembled, so the order in which the installer does things, and the exact registry keys and folders it writes, are not known from this analysis. Those would come from loading the file into Ghidra or IDA. Watching it run in a disposable virtual machine would also show them. Static reading was enough to establish what the file is, who signed it, what it can do and where it fetches the real client from. It was also enough to plan the rebuild.

The decoder is open source: clearbox/analyzers/pe.py. To reproduce the analysis, put the installer in an empty folder and run clearbox scan <folder> -t binary-triage.

Findings

Each finding lists the bytes it rests on, by file offset or import, and states whether it was read directly from a structure or inferred from what was read.

1. It is a downloader, not the application

The version resource names the file installer_stub.exe. The client itself, SpotifyFullSetup.exe, is downloaded from Spotify's CDN at install time, with the CPU architecture inserted into the address.

0x1029fc  OriginalFilename: installer_stub.exe
0x063e92  https://download.scdn.co/SpotifyFullSetup.exe   (UTF-16)

Basis: read from the version resource and string table.

2. The download address is stored outside the code

The URL template sits in a 104-byte block appended after the program image and just before the signature, behind a short binary header. Keeping it out of the compiled code would let one build be pointed at different downloads. That reading of the purpose is ours; the location is certain.

0x103c00  start of the 104-byte block, between .reloc and the certificate table
0x103c3b  https://download.scdn.co/SpotifyFullSetup[ARCH].exe

Basis: read from the section table and file bytes.

3. Its networking is not declared in the import table

None of the eight imported DLLs handles networking. The binary does contain the name WININET.dll and imports LoadLibraryExW and GetProcAddress, the functions used to load a library while running. It most likely loads WinINet that way. Confirming it requires disassembly.

0x0a6d90  WININET.dll
imports   KERNEL32!LoadLibraryExW, KERNEL32!GetProcAddress

Basis: inferred from the string table and import table.

4. It recognizes the Microsoft Store edition

The Store package name appears in the UTF-16 string table next to the Windows app-model API set used to look up installed Store packages.

0x0a64c8  SpotifyAB.SpotifyMusic
0x05d680  api-ms-win-appmodel-runtime-l1-1-2

Basis: read from the string table.

5. It coordinates with Spotify's updater through named mutexes

Four system-wide mutex names prevent the installer and the updater from running at the same time.

0x063218  Spotify Update Mutex
0x063248  Spotify Update Failed Mutex
0x063280  Spotify Update Started Mutex
0x0632c0  Spotify Update Started Interactive Mutex

Basis: read from the string table.

6. It modifies the PC for the current user, without requesting administrator rights

The imports allow it to write, move and delete files, write the registry, change file permissions, refresh the shell, and launch programs. Its strings name the executables it installs and swaps. It imports no function for requesting elevation.

imports   RegCreateKeyExW, RegSetValueExW, SetEntriesInAclW, SetNamedSecurityInfoW
0x0638f8  Spotify_new.exe    Spotify.exe    uninstall.exe

Basis: read from the import table and string table.

What the installer cannot tell us. Nothing about the application's screens or features, which arrive with the client the installer downloads. We did not run it. The recon script in the mySpotify repository applies the same static triage to an existing %APPDATA%\Spotify installation.

Choosing how to rebuild

Spotify encrypts its audio with Widevine DRM. That constraint decides most of the architecture. There are three practical ways for a third-party program to play Spotify audio.

RouteHow audio is playedAssessment
Official SDK (chosen)Spotify's Web Playback SDK, inside a browser engine that includes Widevine: Edge, Chrome or FirefoxPermitted by Spotify's developer terms and stable. Requires Premium, and the player runs in a browser window.
Reimplement the protocolAn open-source library such as librespot speaks Spotify's private protocol and decrypts audio itselfNative and light, but against Spotify's terms, liable to break when Spotify changes the protocol, and a risk to the account.
Desktop wrapperElectron or Tauri around a web appNeither ships Widevine. The Electron build that does requires third-party licensing and adds about 150 MB.

How mySpotify works

mySpotify.exe serves the application's files on 127.0.0.1 and does nothing else. Sign-in, library requests and audio go directly from the browser to Spotify, so the user's access token never passes through the launcher.

Verification

Clearbox examined both programs. The installer's capabilities come from its import table. mySpotify's come from its source code, because its launcher is a Python script.

CapabilitySpotifySetup.exemySpotify
NetworkYes, through WinINet loaded at runtimeSpotify only: api.js line 17, auth.js line 45
Start other programsCreateProcessW, ShellExecuteWNone
Write, move or delete filesYesNone; settings are kept in the browser
Registry and file permissionsYesNone
Background updaterCoordinated through four named mutexesNone; new versions are published as GitHub releases

mySpotify's own tests run on every change. 18 browser checks exercise the real application against a mocked Spotify. They cover sign-in gating, the 2026 response formats, play and save requests, the 10-result search limit, the top-tracks fallback, device transfer, keyboard control, phone-width layout and the absence of page errors. 6 server tests confirm that path traversal is blocked, security headers are sent, only 127.0.0.1 is answered and directories are never listed. Each Windows build also starts mySpotify.exe on a Windows runner and requests the application, its scripts and the sign-in callback before publishing.

Availability

mySpotify.exe is an 8.8 MB Windows program that does not require Python. Its SHA-256 is 0d9d9abe720f8a0aa9bad1a20cba50e5770d9903510c2df2584637f6a8a907a3. Using it requires Spotify Premium and a free Client ID from Spotify's developer dashboard. The setup guide covers both.

The program is not yet code-signed, so Windows asks for confirmation the first time it runs. It opens in the default browser because Spotify's playback SDK needs a browser engine with Widevine. Edge can install it as an app with its own window (Apps › Install this site as an app).

Limitations

  • The analysis is static. Neither the installer nor the full client was run, and finding 3 is an inference that disassembly would confirm.
  • mySpotify's tests use a mocked Spotify. Its first sign-in with a real account is its first live test.
  • Spotify's rules apply. Playback requires Premium, and an app in development mode allows up to five users, each added in the developer dashboard.
  • mySpotify is independent of Spotify and uses only its public API. The installer is not redistributed here; only Clearbox's reports are.
